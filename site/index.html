AGH 驱动的数字逻辑「生成—验证—修复」闭环验证引擎

让 AI 写 Verilog，让编译器、仿真器、综合器和参考实现来判对错。全程不写一行人工测试用例， 失败自动分类、按类给药方、重新生成，直到通过或用尽轮数。

发布日期：2026-10-03　·　智能体底座：Agnes Harness（AGH）　·　模型：agnes-3.0-flash

一、要解决的问题

数字电路教学里一个反复出现的真实痛点

学生写完一段 HDL，验证手段基本停留在「跑几个自己想的波形、看着对就交」。这带来三个具体问题：

  • 测试向量靠人凭经验挑，全 0、全 1、相等、溢出这类边界经常漏掉；
  • 「逻辑完全正确，只是输出晚了一拍」这类错误肉眼极难发现；
  • 不同人写的测试台强度差异巨大，成绩没有可比性。

本项目的做法是把「验证」这件事从人工手里拿走：由规格自动生成测试台与激励，由工具链裁决对错， 并把「验证强度」变成一个可度量的数字——组合逻辑穷举输入空间，时序逻辑用 de Bruijn 序列 覆盖全部 k 阶输入模式。

二、闭环是怎么转起来的

AGH 负责任务规划、能力调用、反馈处理与结果验证四个环节

关键设计：评判标准独立于生成过程。对错由编译器、仿真器、综合器和人工参考实现共同裁决， 而不是由模型自我判断——所以「通过」这个结论是可复核、可复现的。

三、先证明裁判可靠，再让裁判打分

一个会误判的裁判，给出的「通过」毫无价值

校准项做法结果

唯一未通过项 bcdadd 是故意保留的。模型习惯性地实现为「经典 BCD 加法器」（输入按 0~9 处理）， 与本规格「输入按 0~15 二进制相加后取个位」不一致——这属于看似合理、实则不符规格的错误， 正是裁判存在的意义。这里如实保留失败记录，而不是通过改规格或调参把它「做」成通过。

五、失败分类学：不只是判对错，还要说清错在哪

不同类别的失败，给药方完全不同

类别含义修复策略要点
SYNTAX编译失败把编译器原文错误行喂回模型
PORT_MISMATCH端口名 / 方向 / 位宽与规格不符逐项列出差异，要求按契约改写
LATCH综合后推断出锁存器（组合分支不完整）补 default 分支、入口先赋默认值
COMB_LOOP仿真超时，疑似组合反馈环检查无寄存器的自反馈路径
RESET_X复位释放后输出仍为不定态 X检查复位分支是否覆盖全部寄存器
TIMING_SHIFT逻辑正确但节拍超前 / 滞后 ±N 拍超前改寄存输出；滞后去掉多余一级
VALUE_MISMATCH存在与参考实现不一致的输入向量把反例向量表喂回模型

TIMING_SHIFT 是本项目特意做出来的一类：seq1011 的前三轮实现 逻辑完全正确，只是输出晚了一拍。若只做逐拍严格比对，它会被误判成功能错误，修复建议也就跟着跑偏。 这里对两条轨迹做 ±N 拍的平移重比对，把它单独识别出来——该题最终在第 4 轮修好。

七、如何复现

核心链路零第三方 Python 依赖

# 1. 不需要 API Key，先验证工具链与闭环是否通畅
python run.py --list        # 查看 13 条规格
python run.py --selftest    # 元验证 + 用参考实现替代模型走完整闭环

# 2. 接入 Agnes 模型后正式评测
export AGNES_API_KEY=<赛事官方群发放的 Key>
python run.py --all

EDA 工具链使用开源 oss-cad-suite，代码会自动逐级向上寻找 tools/oss-cad-suite， 无需配置环境变量。Windows 下有两点需要注意：DLL 位于 lib/ 子目录，必须一并加入子进程 PATH； 项目所有路径必须是纯 ASCII，iverilog 预处理器处理含中文的路径会失败。
