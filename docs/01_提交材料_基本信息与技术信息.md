## 一、基本信息

### 项目名称

**AGH 驱动的数字逻辑「生成—验证—修复」闭环验证引擎**

### 参考方向（可多选）

- [x] AI 驱动科学发现
- [ ] 工程仿真与优化
- [ ] 智能制造与系统
- [ ] 设计与交叉应用

（本项目同时具备 AI4S 的方法论属性与工程仿真的工具属性；若表单只允许选一项，选 **工程仿真与优化**。）

### 项目摘要（约 250 字）

数字逻辑设计中，「写完一段 HDL 如何确认它真的对」长期依赖人工编写测试台，既慢又难以覆盖边界。本项目以 Agnes Harness（AGH）为智能体运行底座，构建了一个**不需要人工编写任何测试用例**的闭环：给定自然语言功能规格与接口契约，AGH 先做任务规划，再由 Agnes 模型生成 Verilog；随后自动调用 iverilog 编译、vvp 仿真、yosys 综合，并与人工参考实现做逐向量等价性比对；一旦不一致，先对失败做分类，再按类别给出针对性修复策略并重新生成，直至通过或耗尽轮数。

关键设计在于**评判标准独立于生成过程**：对错由编译器、仿真器、综合器和参考实现共同裁决，而非由模型自我判断。为证明裁判本身可靠，项目先用「参考实现自校准 + 已知缺陷注入」做元验证，再投入评测。

### 问题来源与目标

**来源**：数字电路实验教学中反复出现的真实痛点。学生写完 HDL 后，验证手段基本停留在「跑几个自己想的波形、看着对就交」。这种方式有三个具体问题：一是测试向量由人凭经验挑选，边界（全 0、全 1、相等、溢出）常常漏掉；二是「逻辑对但节拍差一拍」这类错误肉眼极难发现；三是不同人写的测试台强度差异巨大，成绩缺乏可比性。

**目标**：

1. 把「验证」这件事自动化——从规格自动生成测试台与激励，不依赖人工用例；
2. 让「验证强度」可度量——组合逻辑穷举输入空间，时序逻辑用 de Bruijn 序列覆盖全部 k 阶输入模式；
3. 让「失败」可被解释与修复——失败先分类，再按类给药方，形成真正的闭环；
4. 让「裁判」本身可信——先用已知缺陷校准验证器，再让它评判模型。

## 二、技术信息

### 1. AGH 在项目中的作用

AGH 是**智能体运行与执行底座**，不是装饰层。它承担四件事：

| AGH 环节 | 具体职责                      | 对应证据                                       |
| ------ | ------------------------- | ------------------------------------------ |
| 任务规划   | 解析规格，判定组合/时序，确定状态机与寄存器设计  | `model_journal.jsonl` 中 `purpose=plan` 的记录 |
| 能力调用   | 通过 MCP 调用工具层（编译/仿真/综合/裁决） | `tools_called` 中的工具调用链                     |
| 反馈处理   | 接收裁决结果，按失败类别选择修复策略        | `purpose=repair` 的记录                       |
| 结果验证   | 判定是否通过，未通过则进入下一轮          | 每轮 `verdict` 字段                            |

工具层以 **MCP（Model Context Protocol）** 暴露给 AGH，暴露 `list_specs` / `verify_candidate` / `describe_verdict` / `stimulus_info` 四个工具，启动方式 `python -m vlab.mcp_server`（stdio，零第三方依赖）。

工具层与本体解耦，因此在没有 AGH 的环境中，用 `python run.py` 可以得到**完全一致**的判定结果——这也让评委可以独立复核。

### 2. Agnes 模型的使用情况

| 项目   | 内容                                                                           |
| ---- | ---------------------------------------------------------------------------- |
| 模型名称 | `agnes-3.0-flash`                                                              |
| 模型版本 | 赛事官方发放的 Agnes 模型，版本号未单独公布，以官方群公告为准；代码内默认值见 `src/vlab/agnes.py` 的 `DEFAULT_MODEL` |
| 调用方式 | HTTPS，`POST https://api.agnes-ai.cn/v1/chat/completions`，Bearer Token 鉴权 |
| 使用环节 | ① 任务规划（plan）② 代码实现（implement）③ 失败诊断后的修复（repair）                              |
| 调用留痕 | `runs/model_journal.jsonl`，逐条记录 purpose / 成功与否 / 时延 / 字符数                    |
| 容错   | 429 与 5xx 按 2s→4s→8s 指数退避重试，最多 4 次；全部失败才放弃该轮                                 |

> ⚠️ 关于模型限制口径：赛事通知正文写「所有模型调用仅限 Agnes 模型」，而赛事官网当前表述为「可自行接入其他合法可用的开源或第三方商业模型」。本项目按**最严口径**执行——**全链路只调用 Agnes 模型**，不接入任何第三方模型。若你在官方群得到明确答复允许放宽，才需要考虑引入其他模型，并在本表如实申报。

### 4. 工具调用链（示例，取自真实运行记录）

```
iverilog -Wall -Winfloop -g2012 -o a.out tb_vlab.v cmp4.v cmp4_golden.v
vvp a.out
yosys -Q -p "read_verilog cmp4.v; hierarchy -check -top cmp4; proc; opt; stat"
```
